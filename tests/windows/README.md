# Native Windows ConPTY acceptance (stacked Draft gate)

This gate is an **OS ConPTY acceptance test**, not a parser-only oracle or Windows
emulation. It belongs to `kvnloo/dsh-tern` and is stacked on Draft PR #2's
`feat/standalone-plugin`. The public `windows-latest` job runs without
credentials beyond GitHub's standard read-only repository checkout. It neither
publishes packages nor launches external model providers.

## Immutable inputs

| Plugin | exact triggering `feat/windows-conpty` PR/push head; build and pack that checkout |
| SDK | `@stencil-hq/tern@0.1.0`, original patched content with SHA-256 `c222b3495ade7f7b334ae4f5f94be05b2b4edb2764645dd1972f90ad436e0998` |

| Native test-only backend | `node-pty@1.1.0`, `node-addon-api@7.1.0`, rebuild tool `node-gyp@13.1.0`; separate `tests/windows/package.json` |
| Windows | real `win32` on `windows-latest`, OS build >=18309; explicit inbox or bundled passthrough ConPTY mode |

The published `node-pty@1.1.0` Windows backend contains both ConPTY and WinPTY.
Every actual spawned instance must have `_useConpty === true`, and its
`_useConptyDll` must match the explicitly selected backend. WinPTY fails.
The default CI mode is separately labelled `bundled-conpty-passthrough`.
It uses the real bundled OpenConsole `conpty.dll`, not kernel32 inbox ConPTY,
and rebuilds the actual native addon with `PSEUDOCONSOLE_PASSTHROUGH_MODE` (8).
The source-only test patch is hash-pinned, applies only when `useConptyDll=true`,
and never modifies the production SDK. The gate verifies the actual loaded
rebuilt addon and records its binary/DLL hashes. Child TTY booleans and source
inspection alone are not acceptance. Real OSC877 frames and Session logs must pass.
After rebuild, `stage-bundled-conpty.mjs` restores the two files that upstream
`scripts/post-install.js` normally copies (node-gyp itself does not copy them).
It uses only `third_party/conpty/1.23.251008001/win10-x64/` from the official
`https://registry.npmjs.org/node-pty/-/node-pty-1.1.0.tgz` package, checks both
source and destination SHA256 values, and stages `build/Release/conpty/`:
`conpty.dll` = `7c7430632052ff703540b68371ec43821820aa1335d8e11dfbcd9ff00e9daaed`;
`OpenConsole.exe` = `d1fe7faa62f9e955e2ac2371f95d7e5513df4d496255097158f979c94782c5fc`.
The transport gate independently checks and records both staged hashes.

## Reproduce on an actual Windows machine (PowerShell)

Start with two separate **clean** local Git checkouts of the exact pinned host
and exact proposed plugin commit. All build artifacts and temporary profiles
remain local; none are uploaded. Substitute only the absolute checkout paths
and the actual final PR head shown on GitHub.

```powershell
$plugin = 'C:\work\dsh-tern'
$host = 'C:\work\deepseek-harness'
$expectedPlugin = '<the exact Draft PR head SHA>'
Set-Location $plugin
if ((git rev-parse HEAD).Trim() -ne $expectedPlugin) { throw 'wrong plugin head' }
if ((git -C $host rev-parse HEAD).Trim() -ne '5badb15009ae1756c3afe0ae0cef1faafc290ccc') { throw 'wrong host head' }
if (@(git -C $host status --porcelain --untracked-files=no).Count -gt 0) { throw 'modified host' }
if ((node --version) -ne 'v24.11.0') { throw 'wrong Node' }
if ((pnpm --version) -ne '11.7.0') { throw 'wrong pnpm' }
node --check tests/windows/run.mjs
if ($LASTEXITCODE) { throw 'ConPTY runner syntax RED' }

Push-Location $host
pnpm install --frozen-lockfile
if ($LASTEXITCODE) { throw 'host install RED' }
pnpm run gen-tsconfig-paths
if ($LASTEXITCODE) { throw 'host aliases RED' }
pnpm run build
if ($LASTEXITCODE) { throw 'host build RED' }
Pop-Location

pnpm install --frozen-lockfile
if ($LASTEXITCODE) { throw 'plugin install RED' }
pnpm run verify:patch
if ($LASTEXITCODE) { throw 'SDK patch RED' }
pnpm run build
if ($LASTEXITCODE) { throw 'plugin build RED' }
pnpm run typecheck
if ($LASTEXITCODE) { throw 'plugin typecheck RED' }

$private = Join-Path $env:TEMP 'dsh-conpty-owned'
$packed = Join-Path $private 'packed'
$receipt = Join-Path $private 'receipt'
New-Item -ItemType Directory -Force -Path $packed, $receipt | Out-Null
pnpm pack --pack-destination $packed
if ($LASTEXITCODE) { throw 'pack RED' }
$archive = @(Get-ChildItem -LiteralPath $packed -Filter '*.tgz' -File)
if ($archive.Count -ne 1) { throw 'pack count RED' }

npm install --prefix tests/windows --no-save --no-package-lock --no-audit --no-fund
if ($LASTEXITCODE) { throw 'native backend install RED' }
npm ls --prefix tests/windows --depth=0 node-pty node-addon-api node-gyp
if ($LASTEXITCODE) { throw 'backend versions RED' }

$env:DSH_WINDOWS_CONPTY_BACKEND = 'bundled-conpty-passthrough'
node tests/windows/prepare-bundled-conpty.mjs
if ($LASTEXITCODE) { throw 'pinned native patch RED' }
node tests/windows/node_modules/node-gyp/bin/node-gyp.js rebuild --directory tests/windows/node_modules/node-pty
if ($LASTEXITCODE) { throw 'real native addon rebuild RED' }
node tests/windows/stage-bundled-conpty.mjs
if ($LASTEXITCODE) { throw 'official bundled binary staging RED' }

$env:DSH_WINDOWS_EXPECT_SHA = $expectedPlugin
node tests/windows/run.mjs --host $host --archive $archive[0].FullName --out $receipt
if ($LASTEXITCODE) { throw 'OS ConPTY acceptance RED; inspect private summary.json' }
```

CI workflow: [`.github/workflows/windows-conpty.yml`](../../.github/workflows/windows-conpty.yml).
The exact **green** run must be read from the Actions UI/logs, verified to match
the PR head and successful job conclusion. Neither adding this workflow nor an
older Linux parser test is Windows acceptance.

## Native proof phases

The runner uses only the existing `tests/host/fixtures/cordis.yml`,
`tui-llm.ts` and `tui-tools.ts` fixture configuration. Those script the
model/provider and harmless workspace-local tool. The normal installed
`dsh plugin --profile tui add <packed.tgz>` command owns all package
installation. The actual DSH loader, CLI, Agent, Session, tool service,
Cordis dependencies and SDK are not replaced.

The mandatory gate checks, in order:

1. Pinned Git/Windows/Node/pnpm and real ConPTY backend prerequisites,
   then independently spawns a native child and proves both child TTY handles.
2. Fresh private profile, real packed-plugin manager activation and
   base-then-external-bundle layering.
3. Real in-band `OSC 877` hello crossing OS ConPTY, real inline `dsh` native
   surface open, APC semantic frames, streaming chunk reassembly, explicit
   `OSC 877` ACKs and nonempty native semantic nodes. ANSI fallback cannot pass.
4. Unicode entry, caret/delete, bracketed multiline paste and enter once,
   plus independently atomic multiline send; exact physical JSONL user intents
   and replies, one real tool-call ID/result, one stable settled semantic card;
   ordinary `/quit` exit **0**, TSP CLOSE and terminal-mode cleanup.
5. Persisted Session resume in a **new ConPTY child**, semantic replay,
   hidden/gone/visible surface recovery and an additional real Agent turn.
6. Native injected protocol error exits nonzero and releases the terminal;
   a freshly opened child successfully negotiates and completes `/quit`.
7. DA1-first ANSI fallback fences malformed/foreign/late APC and OSC 877
   input from becoming a user request; precise persisted intent and response.
8. Explicit `--no-native` never probes a native surface and still completes
   a real multi-turn-capable Agent profile request.

These are eleven enforced phase records, covering seven actual ConPTY child
launches and four independently installed private profiles if all phases run.
A failure stops the sequence, marks the actual RED phase, returns nonzero and
must never be relabeled a green partial check. Existing Linux test assertions
and timeouts are not changed. The absence of native OSC 877 transport is a RED,
not a skipped test or permission to use a parser-only substitute.

## Evidence and privacy

Only `summary.json` is allowlisted for public 7-day Actions artifact upload.
It contains the independent *plugin* Git SHA + packed artifact SHA-256, the
independent *host* Git SHA + clean tracked-worktree result, backend/runtime
versions, native carrier/frame/ACK counts, phase/case names, numerical child
exit statuses and summarized outcomes. The **physical Session ID is never
uploaded**. Physical JSONL Session logs, complete TSP payloads, raw PTY output,
workspaces, HOME, process environments, profiles, prompts, tokens, model output
and credentials are not uploaded or committed. Temporary homes and artifacts
are private to the runner and deleted after the gate; only the allowlisted
synthetic summary survives.

Negotiation failures retain only the existing synthetic transport counters and
booleans for known ANSI fallback/import-failure labels, never raw child output.
Teardown waits for the ConPTY child exit, then closes its pinned node-pty1.1.0
conout worker and input/output sockets before releasing subscriptions and
removing its workspace. A natural child exit does not dispose that worker in
the pinned backend. The isolated shutdown regression checks both paths.
The real-child preflight also reports whether OS ConPTY preserves a known APC
output carrier. This is a transport diagnosis, not a substitute for the
following actual DSH OSC877/native surface phase.

A test-suite exit code of zero and the exact-head Actions job conclusion of
`success` are **both required** to claim a green Windows native gate.
If the OS strips OSC 877 or any other carrier, report that native transport
phase RED with its exact-head job URL. Do not modify the
`patches/@stencil-hq__tern@0.1.0.patch` SDK fix speculatively.
